# CATALAN data-quality audit — forward log 2026-08-07 → 2026-09-25

Generated by `python3 -m catalan.audit.data_audit` (read-only). Every number here is in
`audit_metrics.json` or one of the CSVs beside this file. **Facts** are measured on the full
dataset unless marked *sample*. **Hypotheses** are labelled as such.

**Scope.** This covers the committed archive (`catalan/data/forward_log/`), the system of record.
No prices or returns were read (the NO-PEEK rule is in force), so nothing here speaks to
predictive value.

**Data model** (existing schema, unchanged). One row per NSE corporate announcement:
- **Identity:** `symbol`, `isin`, `company`, `seq_id`. The key is (symbol, seq_id).
- **Text and topic:** `headline` (NSE `attchmntText`) and `category` (NSE `desc`, the vendor topic).
- **Other metadata:** `industry`.
- **Attachment:** `attachment_url`, `attachment_size`, `has_xbrl`.
- **Timestamps:** `announced_at`, `disseminated_at`, `ingested_at`.

There is **no separate description field**. `headline` is the only free text, and any other
content lives in the attachment. AI output rows carry `(model_id, prompt_hash, effort, score,
rationale, run_id, scored_at)`. `model_id` is `claude-haiku-4-5-20251001` and `prompt_hash` is
`1cc1a88738863a44` on every row.

**What each timestamp means.** This is inferred from the measurements above, not assumed.
- **`announced_at` is the exchange publication time.** It is NSE's receipt/broadcast time, about
  30 s after the PDF upload and ≤1 s before dissemination.
- **It is not the event time.** When the board met or when an order was received is only in the
  text or PDF. The drift study needs publication time, so this is the right field, but no event
  time exists anywhere in the metadata.
- **`disseminated_at` is effectively the same moment** as `announced_at`.
- **`ingested_at` is collection time, and its clock is inconsistent.**
  - 34 of 35 files were written by the CI runner, whose clock is **UTC**. One file (08-07) was
    written locally in IST.
  - It is stored **without a zone**, like the IST `announced_at`, so a naive comparison between
    the two is 5 h 30 m off.
  - After correcting for the zone, no record was collected before it was announced. The
    collection lag is median 20.2 h, p90 28.5 h, max 73 h.

**Time of day (IST).**
- 67.5% after 15:30. These are tradable at the next open.
- 31.3% during market hours.
- 1.0% before 09:00 and 0.2% between 09:00 and 09:15.

**Coverage gaps.**
- **Weekdays missing:** 2026-09-04 and 2026-09-11. Both Saturday collection runs failed with
  "nothing collected".
- **Weekend days missing:** 13 of 14. The weekend cron change never reached `main`, and GitHub
  schedules run from the default branch.

## 4. Duplicates

The rules go strongest first. Text identity alone is **not** counted as duplication when the text
is a template (see §5). Two "Schedule of meet" filings by one company on one day are usually two
meetings, so where the headline can't tell documents apart, NSE's byte size is used instead.

| Rule | Records |
|---|---|
| Same (symbol, seq_id) | 0 |
| Same seq_id under another symbol | 0 |
| Same real attachment URL | 5 |
| Same symbol, same second, same headline | 109 |
| Same symbol, same headline, same attachment byte size | 362 |
| **Exact duplicates (union)** | **380 (1.4%)** |
| Near-duplicate: same symbol-day and category, company-stripped text ≥ 0.9 similar, text not a template | 180 |
| Re-filed within 3 days, same symbol, ≥ 0.9 similar, not a template *(upper bound: includes recurring notices)* | 255 |
| **All duplicates** | **815 (3.1%)**, leaving 25,770 unique |
| *Not counted:* same text, same symbol-day, **different** document size | 378 |

**The project's own dedup rule** (`DEDUP_SIMILARITY = 0.6`, same symbol-day, whole headline) was
measured rather than trusted:
- It drops **3,534 records (13.3%)** before scoring.
- For **2,218 of them (63%)**, the dropped record's category **differs** from its keeper's.
- On a hand-read *sample* of 22 dropped/kept pairs, **4 were true duplicates and 18 were distinct
  events**, for example:
  - two different directors' appointments
  - "Issue of Securities – Convertible Warrants" dropped against "Amendment to AOA"
  - "Change in Auditors" dropped against "Outcome of Board Meeting"
- **Cause:** NSE headlines share a long template ("⟨Company⟩ has informed the Exchange
  regarding …"), which pushes whole-headline similarity past 0.6 for unrelated filings.
  (Hypothesis on why the rule was set this way: it was calibrated on US newswire headlines,
  which carry content.)

## 5. Content quality (headline and attachment)

- **Templated headlines.** Strip the filer's name. The remaining text is:
  - identical across **≥5 different companies** for **13,806 records (51.9%)**: "label-only";
  - identical after masking dates and numbers for 14,890 (56.0%): "templated";
  - specific to the company for 11,695 (44.0%).
  - Only 425 headlines (1.6%) contain an amount or a percentage.
- **Examples of label-only text:**
  - "has informed the Exchange about Credit Rating": 291 of 291 records
  - "…about Investor Presentation": 544 of 547
  - "…submitted the financial results for the period ended Jun 30, 2026": 969
  - "…about Schedule of meet": 1,773
- **Attachments** (*sample*: 145 random PDFs, manifest in `pdf_sample_manifest.csv`):
  - Page 1 is a covering letter to the exchange in **97.9%**.
  - 26% are a single page; the median is 4 pages.
  - Text size: first 3 pages median ~1,070 tokens (p90 ~1,880); whole document median ~1,770,
    mean ~13,400, max ~364,000 (annual reports).
  - 14 of 145 (9.7%) have an unreadable page in the first 3 (a scan or a broken font map).
  - One download returned a non-PDF and one failed. 0 hash mismatches on re-read.
- **Obvious noise patterns:**
  - Covering letters: 98% of attachments start with one.
  - Newspaper copies (3,171) and trading-window closures (1,147). These are already excluded by
    the study's filter.
  - Analyst-meet schedule notices: a 1-page letter, median ~440 tokens, in all 19 sampled.
  - AGM notices and proceedings.
- **Not noise despite looking routine:** earnings-call transcripts (in "Con. Call Updates") are
  substantive (median ~11,500 tokens of management commentary), but they arrive days after the
  call, and the first 3 pages are the participant list.
